## 1. Leakage

### What was read

Every module under `features/`, `models/` and `validation/`, and the tests
that enforce the rules.

### Findings

**1.1 No leak found in the current code (note).**
- Feature modules `home`, `schedule`, `goalie`, `shot_quality`,
  `special_teams`, `availability`, `motivation` contain no SQL of their own.
  They read past games only through `history.history_before`, which cuts on
  `h.ended = 1 AND h.start_date < :_cutoff` (`features/history.py:60`).
- Only `features/benchmark.py:37` and `validation/market.py:52` read odds.
- `models/elo.py:90-106` reads `game_spine` and `team_season` only, and
  `tests/models/test_elo.py:141` checks its history equals `history_before`
  game by game.
- Each feature family has a truncation test and a poison test
  (`test_point_in_time.py`, `test_goalie.py`, `test_shots.py`,
  `test_special_teams.py`, `test_availability.py`, `test_motivation.py`,
  `test_elo.py`, `test_harness.py:78`).
- No Liiga competitive game starts outside 09:00–21:00 UTC (query on
  `games.start_utc`), so the UTC-date cut holds.

**1.2 The enforcing tests use hand-written module lists (must, before step 6).**
- `tests/features/test_point_in_time.py:158` lists seven feature modules;
  `:167-170` lists sixteen for the odds check.
- `tests/validation/test_harness.py:245` lists `elo, link, baselines, folds,
  harness`; `tests/validation/test_market.py:145` lists `report, versions`.
- A module added for step 6 (a GBM model, a feature-matrix loader, a blend)
  is in none of these lists. It could select `game_spine.home_goals`, join
  `benchmark_odds` or read `hockey.*` directly, and every test would pass.
- Already outside every list today: `validation/run.py`,
  `validation/metrics.py`, and the five `*_report.py` modules (not model
  inputs, so harmless now).
- The static checks would be complete if they walked the packages
  (`features/`, `models/`, `validation/`) and exempted named modules, so a
  new module is checked by default.

**1.3 Post-game values are used for the game being predicted, by design (should, decision for step 6).**
- `starters.build` (`features/starters.py:143-149`): with no pre-game
  snapshot, an ended game's resolved starter is the actual starter
  (`actual_postgame`). `lineups.resolve_lineup` (`features/lineups.py:143-146`)
  does the same with the actual lineup (`actual`).
- Counts in `features.db`: every row before 2027 is `actual_postgame` or
  `unknown` / `actual`. In 2027: 268 team-rows from a snapshot, 68 from the
  actual starter and lineup (the 34 games with no confirmed snapshot), 752
  unknown (unplayed games).
- The history behind each number is leak-free either way. The skew is in
  *who* is assumed to play: training sees the true starter and lineup; a live
  prediction sees the T-30 snapshot (lineup equal in 268 of 268, starter about
  98%) or, earlier than T-30, the fallback.
- The fallback is stored on every row (`features_goalie.expected_sv`,
  `features_availability.missing_share_10_fallback`), so step 6 can train on
  columns that match the time it will predict at. That choice is not made
  anywhere yet.

**1.4 Season-level columns hold end-of-season values (note).**
`team_season.games_played`, `season_format.runkosarja_ended` and
`season_format.playoff_teams` are as of the build. Elo reads only
`is_first_liiga_season`, and motivation reads `games_per_team`,
`playoff_spots`, `relegation_spots`, all known before the season. Do not join
the other columns as features.

**1.5 `game_spine` carries the target next to the keys (note).**
`home_goals`, `away_goals`, `end_type`, `regulation_result` sit in the table
every feature table joins to. A `SELECT *` join in step 6 would put the
result in the matrix. Covered by 1.2 once the tests walk the packages.

## 6. Step 6 readiness

What the model build needs that does not exist yet:

1. **A game-level feature matrix.** `features_goalie`, `features_shots`,
   `features_special_teams`, `features_availability` and
   `features_motivation` are one row per team per game (12,938 rows each);
   `features_home` and `features_schedule` are one row per game (6,469).
   Nothing pivots the per-team tables to home and away columns or joins them
   to `game_spine`. The pivot must select named columns, never the spine's
   result columns (1.5).
2. **Leak tests that cover the new modules** (1.2).
3. **A decision on prediction time** (1.3): at T-30 with the confirmed
   lineup, or earlier with the fallback columns. It decides which goalie and
   availability columns are trained on, and which odds row a prediction is
   compared with.
4. **A place in the harness.** `harness.MODELS` is a fixed tuple of three
   rating models and `backtest()` refuses anything else
   (`validation/harness.py:34, 270-272`). `harness.load` reads only
   `game_spine` and `team_season`. Folds exist (`first_test` 2018).
5. **Elo as an input.** The pre-game Elo gap is not in `features.db`. It
   exists only in `backtest.db` from 2026-10-13, per fold, for 2018 on. A
   blend needs out-of-fold predictions from both models on the same games.
6. **`lightgbm`** is not in `requirements.txt` (`requests`,
   `python-dotenv`, `numpy`, `scipy`).
7. **A rule for missing values.** NULL means three different things: no
   history yet (first games), no source data (xG and GSAx before 2021, gap
   games), and not applicable (relegation columns in seasons without
   relegation, motivation outside the regular season). xG windows are NULL
   for all of 2015–2020, so those seasons train without them.
8. **Feature rows for unplayed 2027 games exist** (376 games, every table),
   but they are as of the last build. A live prediction needs sync, then
   rebuild (about 45 s, full), then predict, and for a T-30 prediction a
   rebuild between the closing snapshot and puck drop. Nothing schedules a
   rebuild and nothing checks `build_meta` against the last sync or snapshot
   before predicting.
9. **The market comparison is small.** 107 closing lines, all 2027. Elo's
   margin to Pinnacle in `docs/ELO_RESULTS.md` is from 49 games.
10. **`docs/MODEL.md` is thin for step 6**: three-class or two-stage is
    open, the blend is one sentence, and the prediction-log key lacks
    `season` (section 2).

Already in place: walk-forward folds and metrics, the ordered-logit link,
`elo-1` as the reference, a tested truncation and poison pattern, window
game counts and raw rates stored so shrinkage can be tuned inside folds, and
`starter_source` / `lineup_source` as audit columns.
